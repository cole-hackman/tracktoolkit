## Landmines
- Merging to `main` deploys (docs-only, `infra/**`, `**.md` pushes skip it). SQL, App Service settings and retention changes must be done before the merge; ask Cole first.
- `infra/deploy.sh` replaces the App Service settings list: `CHROME_EXTENSION_IDS` and `RETENTION_DRY_RUN` are not in `infra/main.bicep` and vanish on an infra deploy.
- Retention deletes users by `disconnectedAt` (6 days) and `lastLoginAt` (24 months). Never reuse either column for a soft-disable. The 6-day window and the 24h interval clamp are constants on purpose.
- Two memos hold decrypted tokens (`auth-cache.js`, the rotation memo in `soundcloud-client.js`); anything that rotates or revokes tokens must call `invalidateCachedAuth` and `forgetRecentRotation`. Every SoundCloud call needs a token context.
- One worker is a correctness constraint (`numberOfWorkers: 1`, B1 plan shared with `unfollowr-api`), not a tuning choice.
- `prisma db push` from any branch drops the cross-branch tables; schema changes go in as raw SQL against Azure Postgres (`docs/sql/`), by Cole.
- `/health` returning 500 means unresolved Key Vault references (`validateEnv` is global), not a dead app. Build the zip on linux/amd64 only (the workflow).
- Never fetch 1001Tracklists from the server (reCAPTCHA); `/set-to-playlist` works on pasted text only.
- A secret playlist link's `s-` token is a credential: never log it or store it in `OperationLog`.
- Verify runs on every PR (server tests, `npm run lint:server`, tsc and next lint, contrast); it is not a required check, and build and Playwright run only in `npm run verify:full` and the deploy build.
- Flaky e2e: `growth-genre.spec.ts:35` (axe mid-transition) and the downloads "Download all" queue test. Read the Playwright summary for `failed`, not only `passed`.
- Anything pinned to the bottom of an app page offsets by `--mobile-nav-h`. Cole's own window is below `lg`; check UI at his width.
